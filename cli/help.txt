DAY2  /  your platform, from the terminal

Discover what an app can do, what each operation expects, and what it returns.
Detailed text is the default. Use --agent for a single JSON response.

USAGE
  day2 app describe <app> [options]
  day2 instance check <directory> [--agent]
  day2 instance render <directory> [--agent]
  day2 instance plan <directory> <platform> <new directory> [--agent]
  day2 instance apply <directory> <platform> <plan directory> <new directory> [--agent]
  day2 instance release publish <directory> <request> <new manifest> [--agent]
  day2 instance release fetch <directory> <sha256:digest> <bytes> [--agent]
  day2 instance source head <directory> <binding> [--agent]
  day2 instance source archive <directory> <binding> <commit> <new archive> [--agent]
  day2 instance source controls <archive> [--agent]
  day2 instance source verify-controls <directory> <binding> <archive> [--agent]
  day2 instance source checked-artifact <directory> <binding> <commit>
                       <sha256:inputs> <new archive> [--agent]
  day2 instance candidate build <directory> <binding> <commit>
                       <new candidate> [--agent]
  day2 instance candidate preflight <directory> <candidate> [--agent]
  day2 instance candidate check <directory> <app> <candidate> [--agent]
  day2 instance candidate native-build <job directory> [--agent]
  day2 instance candidate native-probe <job directory> [--agent]
  day2 platform --help

PLATFORM OPERATIONS
  platform build SOURCE                   Build and admit an app artifact.
  platform check SOURCE [SEED CASES]        Build and run reproducible checks.
  platform test SOURCE [SEED CASES]         Alias for check.
  platform local-dev [SOURCE] [options]    Build, watch and serve a local app.
  platform backup INSTANCE APP NEW_DIR      Take an online SQLite backup.
  platform restore BACKUP NEW_DIR           Restore into a new directory.
  platform restore inspect BACKUP           Verify and identify an archive; grants no restore approval.
  platform infra plan CONFIG NEW_DIR        Run the pinned OpenTofu planner.

  Platform operations return JSON receipts; errors use stderr and a nonzero
  exit code. Local development runs in the foreground until Ctrl-C.

COMMANDS
  app describe    Inspect an app's operation catalog and typed input contracts.
                  Reads metadata only. Does not invoke operations or sign in.
  instance check  Validate <directory>/day2.json, the instance repository's only
                  authored input, and print every name derived from it:
                  repositories, hostnames, namespaces, images, buckets, state.
                  Every field is required; unknown fields, unsorted lists and
                  invalid or reserved app IDs fail. Reads one file only.
  instance render Validate <directory>/day2.json the same way and print the
                  OpenTofu inputs the platform renders from it: the core roots
                  (project, cluster, tenancy, then app-edge and day2-app per
                  app) in apply order, each with the state bucket and prefix it
                  initializes against and the variables derived for it, as
                  .tfvars.json. Reads one file only; writes nothing.
  instance plan   Validate and render <directory>/day2.json, then run a
                  read-only OpenTofu 1.12.3 plan of its core roots except
                  day2-app, on stacks exported from the spec's platform
                  commit in the <platform> repository. Plans, logs and
                  receipt.json go to <new directory>. Never locks state,
                  creates state or applies; exits 6 if a root fails.
  instance apply  For operators, on a clean checkout of the instance. Plans
                  the same roots with the state lock and applies each saved
                  plan, in apply order, only if its changes equal the ones
                  reviewed in <plan directory>, a prior instance plan's
                  output. Refuses a plan that deletes, replaces or forgets a
                  resource. A failed project, cluster or tenancy root stops
                  the roots after it; a failed app edge stops only itself.
                  Exits 6 if a root fails or is refused.
  instance release publish
                  For operators. Validate <directory>/day2.json, then publish
                  the qualified SDK release <request> describes into the
                  instance's state bucket. Both images must pull as their
                  qualified image IDs; each blob is uploaded create-only (an
                  existing object counts only if its bytes match); the
                  manifest is written to <new manifest> and published last.
  instance release fetch
                  Fetch the approved release <sha256:digest> of <bytes> from
                  the instance's state bucket into the local release cache
                  ($DAY2_RELEASE_CACHE, else ~/.cache/day2-platform-releases),
                  bind the distribution and evidence it names, and print the
                  operator CLI's path. Every cached file is verified on use.
                  Verifies integrity and qualification evidence, not
                  approval: approval is the digest you pass.
  instance source head
                  Validate <directory>/day2.json and <binding>, the JSON the
                  instance's deploy controller binds an app's source with:
                  its forge, org, app, SDK and verification cases must be
                  the spec's. Print the head commit of the bound Gitea
                  branch; the repository must still have the bound ID.
  instance source archive
                  The same checks, then write <commit>'s Gitea archive to
                  <new archive>.
  instance source controls
                  Print the CI-control digest of a source archive with one
                  root directory: every non-Markdown file under .ci/ except
                  .ci/roc.json, and .gitea/workflows/roc.yml. An app's
                  binding approves this value as ci_artifact.digest.
  instance source verify-controls
                  Check <archive>'s controls against <binding>: the approved
                  digest, the qualified SDK release it selects (read through
                  the release cache) and the verification profile.
  instance source checked-artifact
                  Wait up to 35 minutes for <commit>'s main CI run, then
                  verify its one native job, the one receipt the job's log
                  carries, the upload, the downloaded archive and that the
                  attempt has not changed. Write the archive to
                  <new archive> and print its provenance proof.
                  Source commands read the forge with
                  AUTODEPLOY_SOURCE_TOKEN, else GITEA_TOKEN, allowing 90 s
                  until a response's headers and 90 s for each body read.
                  They exit 6 when they refuse and 7 when a read failed
                  transiently: a 408, 429 or 5xx, a dropped connection, a
                  short body or a timeout.
  instance candidate build
                  The candidate for <binding> and <commit>: the stored
                  candidate record, else the checked-inputs record for the
                  same app inputs once the archive's CI controls verify,
                  else a native build of the commit's checked main artifact
                  on the build host. Records are created only while absent.
                  The record's bytes are written to <new candidate>.
  instance candidate preflight
                  Validate <candidate>, then prove on the build host that
                  its tooling image carries the maintenance protocol.
  instance candidate check
                  Validate <candidate> for <app> as the deploy controller
                  validates candidates. Reads no network.
  instance candidate native-build, native-probe
                  On the build host, as root: the job directory's request
                  and files, checked by identity, then the native build or
                  the protocol probe. Run by build and preflight over IAP.
                  Candidate commands exit 6 when they refuse and 7 only
                  when a forge read failed transiently.

OPTIONS
  --demo              Use the bundled Links example; no setup or network needed.
  --instance <path>   Read a local instance.json and its bound artifact metadata.
                      Overrides DAY2_INSTANCE. Cannot be combined with --demo.
  --operation <name>  Focus on one exact operation, such as links.list.
  --agent, --json     One versioned JSON object on stdout, including errors.
  -h, --help          Explain this command, its inputs, and its output contract.
  --version          Print the prototype version.

VALIDATION
  App names are lowercase identifiers of 1 to 48 bytes. Operation names use
  dot-separated identifiers, up to 80 bytes. day2_ and sqlite_ are reserved.
  Conflicting or duplicate source/filter options fail before metadata is read.
  --help cannot accompany describe options; --version cannot accompany a command.
  All model, input, and operation contracts are checked before filtering.
  Malformed, ambiguous, oversized, or unsupported metadata fails as one error.

EXAMPLES
  day2 app describe links --demo
  day2 app describe links --demo --operation links.list
  day2 app describe links --demo --agent
  day2 app describe reports --instance /path/to/instance.json
  day2 instance check . --agent
  day2 instance render . --agent
  day2 platform local-dev ../reports-app

FOR AGENTS
  Never prompts, starts a pager, emits color, or switches format when piped.
  JSON success and failure share schema_version, ok, command, exit_code,
  result, error, and next_actions. Prefer next_actions[].argv over shell parsing.
  Read operation inputs from result.operations[].input_fields; example_input_json
  is a JSON string containing illustrative input, not an executable command.
  Help/version JSON lists implemented_commands and explicit capability flags.
  Exit codes: 0 success/help; 2 usage; 3 context/read failure; 4 not found;
              5 invalid or unsupported metadata; 6 an instance root, a
              release, a source or a candidate command failed, or the
              platform host could not run; 7 a source read failed
              transiently (retryable); 1 output failure.

PROTOTYPE SCOPE
  Local source distribution. Current artifact discovery uses shared runtime
  admission; legacy metadata remains readable. Remote authentication, hosted
  CI deployment and cloud infrastructure resources need provider integration.
