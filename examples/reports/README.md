# Reports

The canonical command/query app, with read-only preparation, durable internal
commands and a shared external notification capability.

Read these files in order:

1. [App.roc](App.roc) registers complete definitions once.
2. [SubmitReport](commands/submit/SubmitReport.roc) creates a pending report and
   atomically requests analysis. [ReviseReport](commands/revise/ReviseReport.roc)
   does the same for a new document revision.
3. [AnalyzeReport](commands/analyze/AnalyzeReport.roc) is an internal command. It
   computes from captured text, then checks the revision and atomically records
   statistics plus a notification request.
4. [NotifyReady](commands/notify/NotifyReady.roc) shows preparation, decision,
   external delivery and private completion in one command definition.
5. [SweepReports](commands/sweep/SweepReports.roc) is reconciliation: it requests a
   notification for every report that became ready but was never announced, in one
   bounded page. [Schedules](schedules/Schedules.roc) is its only caller.
   The instance decides what it runs as: see `schedules` in
   the private instance configuration generated by `local-dev`. A schedule with no actor bound there does not
   run, and says so.
6. [GetReport](queries/detail/GetReport.roc) prepares the notification status and
   projects it with the report. [ListReports](queries/list/ListReports.roc) is a
   simple local query.
7. [ReportInvariants](verification/ReportInvariants.roc) checks business state
   across those phases. Each operation also owns its contract and verification.

`announced` is what makes reconciliation expressible: without a record that a
notification was accepted, "ready but never announced" is not a question state can
answer. NotifyReady sets it on an accepted receipt; ReviseReport clears it, because
a revision withdraws the announcement along with the text it described.

There is no app job definition, worker or retry loop. Reports owns its readiness
state; the platform owns invocation and delivery journals. The notification
adapter is a **local mailbox**, so the example sends no real messages. Its shared
deterministic model and idempotent adapter can be used by other admitted apps.

From the platform repository root:

```console
cargo run --locked -p xtask -- cli
./cli/day2 platform local-dev examples/reports --directory /tmp/reports-command-demo --detach
```

Use a new directory. Open the printed login URL. Submitting a report requests
analysis; the report list and detail statistics update automatically through a
Datastar SSE connection. The detail page also refreshes its notification status
once per second on the server because the mailbox is an external capability.
The local server resumes durable commands automatically. The detached session
supports `--status`, `--logs` and `--stop` with the same directory.

To try live updates, open the report list in two authenticated browser windows.
Create a report in one window: both lists show it appear and become complete.
Open the same report in both windows, start a draft in one, and submit a revision
from the other. The heading and result update while the unfinished draft keeps
its original text and revision. Use **Reload document** to deliberately load the
latest document before editing it. Reconnecting the live stream reads a fresh
snapshot, so closing and reopening the connection catches up to current state.

[Routes.roc](pages/Routes.roc) enables the existing list query with `.live()` and
the detail query with `.live_refresh_every(1000.U64)`. Queries keep their normal
command/query contracts. In the HTML templates, `data-live` marks stable regions
with literal, unique IDs. Region wrappers stay outside conditional branches and
loops; their contents can change freely. Forms remain outside these regions so
server updates preserve input drafts and the expected revision they were based on.
Command forms also have stable, unique literal IDs: command responses refresh only
the acknowledgement and, after success, the submitted form. The stream updates the
live regions. A rejected edit keeps the original draft and revision; submitting a
stale revision never silently rebases it onto someone else's changes.
Use `.live_refresh_every(milliseconds)` with a value from 1000 to 60000 for queries
whose external reads or time-dependent output can change without a business write.
The app declares this policy explicitly; `.live()` alone follows local business
data commits and does not infer changes to external capabilities.

The [runtime guide](../../docs/COMMAND-RUNTIME.md) explains SDK contracts
first, then journal implementation, provider ambiguity and simulation testing.
The [layout guide](../../docs/APP-LAYOUT.md) covers adjacent nominal request
types and generated handles. Preserve `model-identities.json`: reports retain
their `rep_` UUIDv7 identity and `RowVersion` revision contracts.

From the repository root, run `cargo run --locked -p xtask -- verify` for the complete public gate.
