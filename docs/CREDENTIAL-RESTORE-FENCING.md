# Closed restore incumbent-drain foundation

This is an uncallable production foundation, not restore approval or native
fencing. Approval and complete-stop origin enums have no production variants;
the sealed source has no production or default implementation. Controlled tests
supply a model, not real first-holder, writer, P3 or serving owners.

A session retains one original approval and the same exclusion source. Before a
possible stop effect it permanently marks that approval used. An unknown stop
reply, any failed check, caught unwind or dropped session refuses the actual
approval and source; fixing the input cannot retry the stop. Postchecks run on
primary failure without replacing that primary cause.

The future real stop supplier must atomically prevent new issuance and renewal,
including in-flight sends, and freeze a complete bounded inventory of every
incumbent lease and executor/stage final-action permit. The mechanical bound is
1,024 strictly ordered unique identities, without truncation. A process list,
lease count, receipt, pidfd death or filesystem lock is not complete exclusion.

The wait path uses authenticated lower/upper clock bounds in one qualified clock
domain. The lower bound must reach the frozen maximum expiry, and every upper
bound must remain strictly before the original approval expiry. Equality at the
approval deadline, rewind, changed inventory, changed source or an original too
short to cover drain refuses. No duration is selected here; approval governance,
its genuine issuer and its fixed interval are pending user policy.

Every consuming boundary must freshly join the same session, exact operation,
namespace generation, source/target epochs, selection, roots, holders and target
incarnation. A cloned opaque original identity is continuity DATA only. Equal
metadata from a different approval does not join, and a copied identity cannot
outlive refusal or expiry or construct any authority.

Physical fencing is not implemented. A future alternative must exclude every
exact descendant, duplicate and remote right, not merely the visible processes.
No old database is changed, no creator file is adopted, and no new writer,
publication or serving constructor is added by this foundation. The next
mechanical step must retain the actual staged creator and freshly verify its
private frozen reset image plus genuinely current settled/fenced root and real
P3/writer/peer admission under this same original.

## Native final-response tickets

Each actual installed App or Shell owner now retains its response-rights ledger.
App capture registers with that exact owner before attempting the native request
original. Unselected Shell capture conservatively registers every actual installed
Shell scope before the attempt and refuses if a scope is currently leased out.
Routing clones share the same ticket set. A per-poll Current completion, peer ACK,
SQLite close, cleared response binding or request-original finish retires nothing.

The retained App driver validates exact creator/owner/registration bindings and
prepares the terminal continuation before consuming the original. It keeps that
continuation outstanding through the actual fallible `transport.complete`. Only
after result publication and both known dispositions does infallible local Cell
bookkeeping retire the tickets. No new terminal RPC, clock, callback, allocation
or fallible borrow is appended. The ordinary connection-completion and autonomous
request paths use the same retained terminal bookkeeping at their actual endpoint.
Abort, lost publication, cancellation, owner loss and unfinished Drop leave rights
unresolved. Unknown records are never pruned or cleared by a guessed timeout.

This is the real response-right hook, not a complete cohort Stop supplier. No
complete-stop constructor, restart adoption or accepting restored writer is
added. Dispatch/observation/provider child rights, persistent keepers, remote
bearers, Controller issuance and the full historical cohort still need their
actual hooks or explicit supported-profile refusal before creation. Completing a
parent response cannot establish that those separate rights have terminated.
The closed restore-authentication owner remains administrative; no arbitrary
`AdminRead` or `CurrentRole` callback is exempted from business accounting.
