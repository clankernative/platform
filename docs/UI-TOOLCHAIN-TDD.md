# First-party UI toolchain — implementation checkpoint

This is a review checkpoint, **not a claim of complete verification or production readiness**. No CI vendor, release publication, repository visibility change, deployment or Linux isolated-builder port is selected here.

## Ownership

Apps own pure Roc domain decisions, complete operations, routes, HTML declarations, browser presentation and theme overrides. An optional build-time producer expands presentation. Platform independently captures and admits ordinary templates/resources and serves immutable artifacts without invoking the producer at runtime. Studio reads generic artifact contracts and edits revision-checked presentation sources; it does not own business authority.

[Editable drawings and PR/TDD image previews](architecture/ui-toolchain/README.md) illustrate the build boundary and the saved-source/static-preview/admitted-app distinction. Drawings describe intent, not verification evidence.

## Contracts and composition

- One canonical `ui/ui.lock.json`: schema 1, provider and nested package identity, relative path, sorted complete declared input manifest and digest. Legacy flat locks are rejected. Package updates are explicit.
- Assembly protocol 2, binding ABI 2 and MiniJinja 2.12.0. Platform and preview independently check identical 99-case vectors; Platform has no component runtime dependency.
- Explicit local or exact-version hosted archive acquisition precedes compilation. Safe installation verifies bytes and publishes to a fresh directory, but does not execute the compiler or authenticate provenance. Operator execution approval is separate.
- Generic `ui_key` admission accepts field-only primitives and already checked nominal `Ref(Model)` identities. It does not accept literals, computed expressions, booleans or unknown shapes. Output decoding still validates registry-bound prefixes and canonical UUIDv7 before rendering; key syntax alone is not nominal validity, row-existence or authority proof.
- Generic contract export is artifact-bound, bounded and read-only apart from its explicit output. Private atomic output preserves hardlinked artifact inputs. Parent directories must be operator-owned and stable; this is not hostile-parent containment.
- `ops/AppCreate.roc` composes optional `day2 platform app-create`. UI-free/HTML remain first-class; Clanker uses an explicitly approved installed vanilla bundle. Its package is outside `ui/`, with no app-owned executable approval. See [app creation](APP-CREATE.md).
- GoLinks uses supported headers, surfaces, layout/action groups and rich tables. Domain operations, cursor paging, `app.js`, edit contracts and live IDs remain app-owned. Installed dependency placement replaces sibling-source provisioning; package identity and all 448 input hashes remain unchanged.
