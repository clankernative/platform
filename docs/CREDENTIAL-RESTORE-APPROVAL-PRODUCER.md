# Native restore approval producer

The producer consumes a genuine existing authentication-store action. It does
not open an ordinary database, initialize missing state, accept a scalar clock,
or construct native permission from a signature or saved row. Live deployment
and native qualification are separate from this implementation.

The issue action selects a current reviewed passkey under current admin policy,
creates a fresh server challenge over the complete timestamp-free intent, and
qualifies actual host time against the external safe floor. It create-only saves
the pending challenge and closes the actual authentication connection/file lease
and accepting reader before returning challenge DATA. No native owner or App
read exclusion survives the human wait. The ceremony is a single server-owned
continuation; a restart cannot reconstruct it from a pending row.

Completion uses another genuine current action. It commits the claim before
verifying the real UV-required WebAuthn assertion. Both the claim and final
counter/verification commits have actual SQLite descriptor and native checks
before and after, including a failed commit. Ordinary registry-read keys cannot
substitute for the authentication-file loan. Unknown refusals keep their typed
causes beneath the fixed outer error; known assertion denials return DATA only
after mandatory current-source postchecks.

After known verification, the producer samples actual enrolled-controller host
time and advances the external floor conditionally. All four root records, the
prior floor and receipt absence are read in one provider read/write transaction.
The two writes use that transaction, an exact floor version and create-only
receipt. Known acknowledgement and a fresh coherent readback must agree before
the native source qualifies time. Missing floor state refuses, never defaults
to zero. The floor and immutable receipts are outside both the App archive and
the authentication SQLite file.

The private completed owner freezes one approval time and exactly one hour of
validity. The journal create-only binds the verified challenge and complete
statement, then commits MaySign before any signer call. Every SQL transaction
closes before configuration/provider I/O or signing. No row is a recovery entry
to the completed owner. Interrupted or ambiguous work needs a new ceremony;
neither a later clock nor a fresh HTTP original renews the frozen times.

The signer credential is minted for the actual selected Controller identity and
the fixed Cloud KMS scope only after UV, qualified time and the known MaySign
commit. The native source signs only the exact reviewed restore key version and
full canonical statement. Version state, algorithm, public bytes, CRCs and local
signature verification remain mandatory. Each actual request and response/body
read is bracketed by the completed owner's current registry, original clock and
native checks. Key removal or selection change refuses pending work.

Publication is create-only in the separate authority/grant-keyed publication
namespace. It retains the exact full signed record and is conditional on the
same root/time read set, followed by strong coherent readback. The local journal
records that known publication. The record is returned only after final native
source checks and actual authentication SQL close, file checks and reader
settlement. A commit followed by refusal withholds the result; it does not
promise rollback or completed delivery. No unknown result is retried.

The signed executor identity is an exact binding, not proof that an executor was
present or consented during issuance. The approver's UV proof cannot stand in
for a distinct executor. The accepting operator command must freshly authenticate
that exact current admin, revalidate target/archive/custody and use the genuine
external single-use/Fenced transition. That consumer is separate work. Neither
publication parsing, a local published row nor the signed record constructs its
native owner. Existing custody is retained; no restore migration is introduced.

The existing five-second originals, earlier ceilings, permanent refusal and
last-close WAL/SHM unlink refusal remain. This adds no native ledger/floor birth,
persistent keeper, complete stop, accepting writer, cloud resource or IAM grant.
Qualification must establish the concrete supported native profile and timing.
