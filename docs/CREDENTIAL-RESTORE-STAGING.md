# Private credential restore staging

The private staging code captures one SQLite image through a held source file,
validates its complete current credential unit, and performs the complete
application denial reset in a fresh memory-only database. The staging owner
opens the sole outer transaction; the prepared application selection supplies
the same fence, canonical schema references and inventory cut to the existing
SQL-only reset. The cut must match the staging namespace and source epoch.
The selection also lends its actual immutable loaded artifact. Exact artifact
and schema identity must match the cut and the source authority; an ordinary
rollout admission is not an alternative. The existing canonical storage reader
validates all model rows, including tombstones, codecs, IDs/versions, foreign
relationships and rollups on this same scratch transaction before any denial
write. Loading the artifact and checking the complete archive graph remain
outside this unit. This structural storage check does not run app properties
or establish native backup provenance or artifact admission by itself.
There is no second autocommit reset path or transaction held over provider,
artifact, entropy or filesystem work. It freezes the resulting bytes before creating
a new target, using directory-relative creation under the held root and private
directory descriptors. It writes only through the actual creator descriptor,
then syncs and checks the exact readback. Memory commit records prepared DATA;
physical writes and durability checks remain separate effects.

The scratch connection is configured once, before deserialization, model reads
or integrity checks. A private continuous mutable borrow lends the actual outer
transaction and one-use hook proof; the proof cannot be cloned, rebound or made
from memory PRAGMA data. Complete reset admission uses that same installed
runtime progress callback. Nested admission never replaces or removes it, on
success, refusal or unwind, and beginning a transaction never renews already
spent work. The connection's original execution limit stays active through
commit, serialization and close. These are scratch-SQL ownership guarantees,
not native storage, archive, approval or writer authority.

The first profile bounds the image to 16 MiB, lineages to 1,024 and versions to
4,096. It requires an existing complete canonical credential unit with foreign
keys enabled. Unknown or partial schemas, foreign namespaces or source epochs,
unclosed or foreign peer history, WAL images and sidecar files refuse. Retained
canonical peer history is admitted only through the concrete full-reset cut
inside the same transaction. Sidecar absence and
SQLite integrity do not establish committed-backup provenance: the future
maintenance supplier must bind the exact verified cold archive.

Reset uses the existing active-to-revoked transition. Original epochs, grants,
identities, custody envelopes, receipts, reveals and origin history are retained;
delivery closes through that same transition. It does not retag ciphertext or
reissue credentials. A replaced or revoked credential remains refused. Business
rows in the admitted profile survive. The same reset disables the old application
authority, invalidates old sessions and ticket secrets, fences delegations,
freezes budget debt and marks imported OAuth connections for fresh
reauthorization. Existing uncertain refresh and external-effect history stays.
The ordinary restore refusal is unchanged.

The production accepting boundary remains closed. The native Parent retains one
actual fenced write loan alongside the same staging state and immutable
selection. A closed concrete context dispatches either to that actual Parent or
to the existing unqualified portable source. Both use one reset, SQL and file
body. No manual authority trait, native callback table, role/descriptor/HTTP/
connection getter, new stage or new original is introduced. Full checks delegate
to the actual loan outside SQL; local checks use only its SQL-safe check.

Explicit failure refuses the same loan. Loss must retain the actual supplier's
nongeneric lost-loan guard; a Parent-local flag or generic destructor cannot
replace that contract. The accepting constructor remains absent until exact
approved target binding, creator/P3 admission and fixed native writer
transitions are supplied. The later generation handoff must preserve sealed old
history and the same Controller original; it cannot reinstall an empty ledger,
unseal the issuer or cold-enroll a replacement as proof. Only tests
can currently construct staging owners; no default implementation, public command,
Runtime opener, native factory, target adoption or publication path is installed.
The test application validator is synthetic. A staging projection supplies
counts and image identity only. It now describes the concrete whole reset that
ran before memory commit, serialization and close, but cannot establish actual
archive/artifact/model admission, current external epoch settlement, a new
writer or serving readiness. No production checks implementation exists yet;
the complete admitted artifact/profile and same creator must remain held by
the future genuine native supplier rather than supplied as a summary.

A usable restore additionally requires designated restore approvers and
executors, genuine approval evidence with one fixed original deadline, exact
custody-key authority, external reservation and settlement, old-owner fencing
and drain, actual artifact/profile admission and the same-created target's new
writer. Enrollment, bootstrap or OAuth trust does not implicitly grant restore.
The operational recipe belongs in Roc and must publish last. Neither a previous
staging projection nor a reconstructed descriptor can renew an uncertain attempt.

The conformance suite uses real SQLite and descriptor I/O, an independent
commit-cut oracle with full application-state readback, twice replay,
source/target and creation-parent pathname swaps and actual process
loss followed by reopen. Reopen is an oracle observation; it never adopts an
existing target. Local process-loss tests make no power-loss, Linux, hostile
filesystem containment or live-provider qualification claim.

## Owned native archive input

The bounded capture component consumes the actual authenticated executor before
reading the archive. It retains that executor through capture and preparation;
a failed or unwound capture drops its real original, source and file owners.
Chunk reads use the same original and retained local checks. Complete current
checks remain at capture entry and exit and at each worker launch and contract
exchange. Each exchange computes its timeout from a fresh observation of that
same original, capped by the existing three-second worker limit. A failed
postcheck discards its result and closes the owned child. A synchronous OS call
can return late; late return never publishes a successful admission.

The first native profile handles exactly backup.json, app.sqlite and the one
current bundled artifact. It refuses provider stores, rollout and companion
state, sidecars and unlisted members, including empty unhandled directories.
The manifest is at most one MiB, the SQLite image sixteen MiB, and the artifact
at most 256 MiB with sixty-four MiB per file, 4,096 total entries and depth eight.
Reads use no-follow directory-relative descriptors, identity checks and retained
captured bytes. The shared artifact validator sees only an owned private copy,
with its file and directory descriptors and complete inventory retained.

The native full-capture commitment uses the domain
`day2-native-restore-archive-v1` and profile `sqlite-current-artifact-only`.
It commits the separate semantic manifest commitment and the sorted complete
member map. File entries contain kind, byte length, SHA-256 and observed source
permission bits; directory entries contain kind and source permission bits.
The empty path denotes the archive root. Raw manifest bytes, the database and
every artifact member are included. UID, inode, timestamps and absolute paths
remain native ownership checks and are not portable approval identity. Changing
JSON formatting, a file mode or an empty directory changes this full commitment.
The signed approval must match this actual commitment before worker admission
or staging-state construction. Metadata-only operator inspection does not
produce it; the actual approval-side capture producer remains separate work.

The exact captured SQLite bytes become a Linux sealed memfd before the private
staging entry. Write, growth and shrink seals are mandatory, with no accepting
fallback. Staging takes that actual owned descriptor and never reopens the
archive pathname. Its complete schema, storage, authority, artifact, namespace,
custody and denial checks remain in place. The SQL authority epoch string is
not interpreted as the native security epoch. A fresh application authority
identity and qualified delegation cutoff are prepared outside the reset SQL.

This component does not establish the remaining artifact installation,
receiving App admission, P3, writer activation or keeper handoff, nor does it
supply an operational restore command or native qualification. The prepared
owner can enter only the actual private fenced writer, preserving the same
executor and retained capture; decoded inventory or a digest cannot enter it.
