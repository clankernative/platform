# Atomic offline reset composition (private foundation)

The application reset combines local denial in one memory-only transaction:
fresh disabled authority, deleted web sessions/ticket secret, frozen budget
admission with unchanged usage and unknown debt, a monotone delegation fence,
the complete OAuth/Fresh continuation cut, and canonical managed-credential
revocation/delivery closure. Credential ciphertext, receipts, reveal history,
browser/confirmation history and inherited origins remain historical DATA.

The successful OAuth cut returns a private transaction loan. It has no raw
connection getter or generic callback. Its only credential continuation calls
the canonical revocation operation under a context bound to that actual
transaction, the same disabled authority and the same applied cut/namespace/
source epoch. Merely loading cut rows cannot construct this loan. The loan
ends before the sole outer commit; the transaction rolls back on error.

The ordinary credential-only reset still refuses occupied peer history. The
complete profile validates all existing peer rows through the current owning
installer before retaining them. No imported schema is repaired or restamped;
there is no callback cancellation-column fiction or old-format fallback.

The SQLite unit schedules have an independent two-state oracle. They exercise
transaction drop after a complete denial, an error caught before an outer
commit, repeated reset, preserved uncertainty and debt, and two reopened DATA
observations. Each of twelve bounded schedules runs twice. A failed setup,
step or assertion retains both completed prefixes, the full seed/action input,
independent expectations and selected owner/dependency source identity in a
private create-only record of at most 32 KiB. It contains only typed synthetic
booleans/counts, not token material, snapshots or error strings. CI retains it
under `artifacts/credential-restore-application-histories/failure-*/failure.json`.
Setting `DAY2_OFFLINE_RESTORE_REPLAY` to one such record adds its exact-source
replay after the mandatory twelve schedules; it never replaces them.
An exact match reports failure reproduction, not a successful model campaign.
An explicitly requested reproduced failure returns a fixed failing campaign
status, even when the mandatory schedules passed.
Recorder fault-injection controls use separate temporary files and are refused
by the real campaign's exporter, so CI never mistakes those controls for an
actual reset counterexample.

These unit schedules neither construct native owners nor qualify a loaded app
artifact. Transaction drop and reopened copied DATA do not establish native
process-loss, durability or power-loss behavior. Real browser/confirmation
consumers after activation and physical writer qualification remain separate.

This composition does not authorize restore or copying. The native accepting
caller still needs the actual consumed approval/maintenance original, qualified
clock, old-holder exclusion, full archive/artifact/model admission and retained
creator file. Existing pre-fence issuance owners and their HTTP clocks cannot
be retagged as post-fence storage authority. Counts or local commit cannot
create current-root, first-holder, P3, writer or serving permission.

The earlier complete-reset composition passed its real SQLite/model and
late-fault controls, complete inventories, formatting, architecture enforcement
and normal local verification. The public draft includes newer foundation and
main changes, so those results do not qualify this composed head. Its current
local and hosted checks, exact-head reviews, native accepting owner and physical
writer qualification remain separate requirements.
