# Protected restore: operator procedure under construction

This procedure follows the protected restore qualification plan. Its recipe is
[SecureRestore.roc](SecureRestore.roc). The private Runner's `secure-restore-plan`
entry emits only the fixed plan as JSON. It reads no operator input and performs
no effects. There is no executing protected restore command in this skeleton.
Rebuilding the pinned workflow runner is required before its preview is available.
The ordinary `platform restore` path still refuses secured state; it cannot
substitute for the protected accepting path.

## Preparation and approval

1. Obtain the coordinator's qualification sign-off. Root owns native runs and
   cleanup. Obtain the user's approval before creating resources or spend. Select
   disposable test installations and a protected evidence destination. Never use
   GoLinks state for this campaign.
2. Select the exact immutable archive digest, target, security epoch, executor
   identity and the app's existing vault binding. Resolve the complete archive
   key-version set; an identifier alone does not establish key availability.
   Do not change custody, use a key alias, or choose a different target after
   approval. Verify archive integrity before any target mutation.
3. Use the current reviewed instance registry and an admin in `policy.admins`.
   The real user performs the passkey ceremony with user verification, the exact
   configured RP ID and origin, and the server challenge bound to the full
   request. A CLI assertion or boolean is not approval. Removing the registry
   key invalidates pending ceremonies and new approval use.
4. The genuine producer verifies the assertion, durably consumes the challenge,
   and signs and publishes the exact-purpose grant with the selected signing key
   version. It lasts exactly one hour, cannot renew, and is single use. A durable
   verified assertion, MaySign row, publication row, or HTTP success does not
   establish delivery or a surviving native signing owner. Do not recover an
   owner from any such row after a crash.

## One protected accepting turn

The following stages describe obligations of the existing native composition,
not independently invocable recipe capabilities. The whole real owner, captured
original and retained resources must survive the turn. No authority or owner
travels through JSON between stages. The one-hour grant never extends the
short captured original; do not reset its clock after waits or failures.

5. Authenticate the current executor with the distinct execution ceremony. The
   executor is an instance admin and may be the approver. Recheck the current
   registry, approval signature, exact request and executor; capture the genuine
   current request before queueing or work.
6. Hold App exclusion and the authenticated admin read loan across complete SQL
   units and Controller auxiliary handles. Retain the actual SQLite main, WAL
   and SHM identities from before first activation, with the keeper and write
   exclusion intact. Obtain and retain every required historical key under the
   current authority. A fixture, copied descriptor identity or manifest is not
   a replacement supplier.
7. Commit the grant-keyed execution marker before any reservation send. Stop and
   drain the real issuer/peer cohort and all outstanding authority, including
   escaping provider rights. Fence such rights or refuse. Consume the grant and
   reserve the epoch atomically under exact current versions, with a known
   result and complete exact readback. The reviewed native accepting order is durable attempt marker, issuer freeze,
   stop announcement, actual stopped acknowledgement and issuer postcheck, then
   the single reservation CAS and known readback. Both complete stop and known
   reservation precede reset and writer handoff. This planning recipe does not
   create an alternate stop/CAS protocol.
8. Stage and reset the exact archive while holding its actual creator and the
   same owner. Revoke old credentials, close callbacks and require OAuth
   reauthorization. Retain historical denial and budget records. Activate only
   the exact reset writer under current authority; never adopt a partial or
   reopened target as an active writer.
9. Install the Controller and App using the actual retained parents, exact
   runtime/files and genuine peer acknowledgements. Acquire a fresh Controller
   Current on the restored connection. Install the Host only after its required
   startup settlements; publish routing and enter the listener loop last.
10. Complete the actual finite response transport and all final native,
    original, target, cohort and counter checks on that same request. A prepared
    reply, installed record, peer ACK, SQL settlement or success status is not
    final delivery. Output failure may follow committed writes or transmitted
    bytes; it does not promise rollback or erased output.

## Qualification and retention

11. Demonstrate both a fresh ordinary Controller Current and actual ordinary
    restored Host traffic with the supported route/consumer bindings. Observe
    that old credentials and callback work refuse and OAuth requires new
    authorization. Installed DATA or an HTTP status alone is insufficient.
12. Run each recipe refusal case on a separate disposable setup: child death
    and uncertain commit; wrong target, key, epoch and executor; expired and
    consumed grants; removed registry key; late peer death; final-output
    failure. Use the qualification matrix to distinguish existing crypto,
    SQLite, process and model evidence from still-missing native cases. A
    normal child exit is not a demonstrated kill. Commit uncertainty is
    terminal even when later readback shows the write occurred.
13. Retain the exact source/toolchain identities, bounded allowlisted joins,
    actual first failure, child status/EOF, commit cuts, authority state and
    final transport disposition in protected evidence. Never log assertions,
    grants, tokens, key material, full process arguments or environments.
    A summary may reference protected evidence without copying its secrets.
    Root then performs the authorized guarded cleanup, preserving evidence and
    other workers' resources.

Any refused, expired, ambiguous or abandoned accepting turn permanently refuses
its real owner. There is no resume from a receipt, automatic retry, repaired
clock, replacement original or fresh login that can reuse a consumed grant.
A later authorized attempt needs its own genuinely new prerequisites. The
campaign must not report success until the callable protected producer and
accepting path, real Controller and Host, and refusal matrix have their own
current-source qualification evidence.
